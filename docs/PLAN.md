# 工作区分组（Workspace Groups）实施计划

> DSH 左侧工作区「项目分组」插件 —— 完整设计文档
> 版本 v1 · 目标：把「一个项目一个文件夹」的平铺左栏，变成 **分组 → 项目 → 对话** 的三级可折叠树。

---

## 0. 一句话目标

在 DSH Web 左侧工作区区域，用**分组（Group）**把工作区（项目）归档收纳：可改名、可换色/换图标、可拖拽入组与排序、可置顶、可归档、可搜索定位、可纯键盘操作；折叠状态与全部元信息**持久化**，重启后完全还原。

---

## 1. 范围（Scope）

### 1.1 必做（Core）

| # | 能力 | 验收标准 |
|---|---|---|
| C1 | 分组树：组 → 项目 → 对话 | 组头折叠态、项目折叠态各自独立保存；展开链 `组展开 → 项目展开 → 对话行` |
| C2 | 组改名 / 改色 / 改图标 | 组头立即生效，重启后保持；颜色只用在图标与小圆点 + 左侧 2px 细色条 |
| C3 | 拖拽 | 项目拖到组头 → 入组；拖到「未分组」区 → 移出；组头之间可拖动排序；有插入位置指示线 |
| C4 | 删除组 | 弹二次确认，两个选项：**解散组**（项目回到未分组，默认）/ **连同项目删除**（同时注销工作区）；默认前者 |
| C5 | 折叠持久化 | 组/项目/「查看全部」三级状态写入 Host，重启后保持 |
| C6 | 色板 + 图标 | 8–10 预设色（深浅色主题各自一档亮度）+ 通用图标集（文件夹/星标/代码/文档/方块/烧瓶/火箭/Bug），不做自由取色器 |
| C7 | 搜索 | 一个搜索框同时匹配 **组名 / 项目名(含路径 basename) / 对话标题**；结果显示所属组路径 `组 › 项目 › 对话`；点一下自动展开定位 |
| C8 | 默认折叠策略 | 组默认展开、项目默认折叠（只显示最近 1–2 个对话 + 「查看全部 n 个」） |
| C9 | 「全部折叠」快捷键 | 全局快捷键一键折叠所有组；菜单里也有等价入口 |

### 1.2 增强（Deluxe，同批交付）

| # | 能力 | 说明 |
|---|---|---|
| D1 | 组头元信息 | 有未读/运行中/待确认时显示计数小徽章；否则显示「最近活跃」相对时间 |
| D2 | 右键菜单 | 项目行「移动到组 →」子菜单（同时是拖拽的键盘替代路径）；组菜单含改名/换色/换图标/置顶/归档/删除 |
| D3 | 新建项目选组 | 组头 `+` 直接在该组新建项目；顶部 `+` 新建到「未分组」 |
| D4 | 置顶区 | 组可「固定到顶部」，置顶组排在非置顶组之前，且组内顺序独立保存 |
| D5 | 键盘导航 | ↑↓ 移动可见节点、→ 展开、← 折叠、Enter 进入对话（组/项目则为展开），配合搜索框可纯键盘查找 |
| D6 | 视图切换 | 「分组树」⟷「最近使用」平铺（按最近更新时间倒序），一键切换并记忆 |
| D7 | 空组提示 | 空组显示淡色虚线区「拖项目到这里」 |
| D8 | 归档 | 组可归档：离开主列表，进入底部「已归档」折叠区，可恢复 |
| D9 | 无障碍 / 主题 | 折叠箭头 `aria-expanded`、树节点 `role=tree/treeitem`、拖拽有菜单替代路径；深色模式色值自动提亮一档 |

### 1.3 不做（Non-goals）

- 不做自由取色器（RGB/HEX 输入），只给预设色板；
- 不做多级嵌套分组（组是单层容器，避免无限树与心智负担）；
- 不接管对话内容、不改会话日志、不写新的 session 事件类型；
- 不做跨设备同步（本地持久化即可）；
- 不改动 DSH 自带 `ui-workspace` 的 Remote 契约与 Host 数据（只读它 + 复用它的公开动作）。

## 2. 落地位置与架构

### 2.1 为什么是「替换 `sidebar.workspaces`」

DSH 左栏的浏览区是一个 `single` 槽位：`sidebar.workspaces`（由 `ui-sidebar` 声明、`ui-workspace` 的 `WorkspaceBrowser` 占用）。列表结构、搜索、行渲染整体都在这个组件里，**没有任何「额外区块」槽位**可以插进平铺列表中间。因此本插件注册自己到 `sidebar.workspaces`，以（动态插件天然获得的）更低 priority 遮蔽原 Browser，接管整个浏览区。

被遮蔽的原 Browser 仍然在槽位上注册，所以它声明的子槽（`sidebar.workspaces.session.row.action` 等）依然存活；**本插件不声明任何子槽**，以避免「同一子槽被两个 entry 声明」的激活冲突。取而代之：

- 行的右键/「…」菜单 → 复用全局 `ctx.contextMenus`（`target: 'session'` / `'workspace'` 的内置动作仍然在，改名/分支/复制 ID/归档/置顶照旧可用）；
- 本插件追加自己的菜单族：`target: 'workspaceGroup'`（组动作）与 `target: 'session'` 的 `移动到组` 子菜单；
- 目录选择 → 直接调用 `ctx.get('uiWorkspace').pickDirectory()`（原 `directoryFlow` 子槽不再使用），再用 `ctx.get('workspaces').create({path})` 落库。

### 2.2 数据流

```
Host 侧（plugin/index.mjs）
  ├─ 原子 JSON 存储  ~/.dsh/workspace-groups/state.json
  │    { groups, assign, orders, archivedGroups, ui }
  ├─ GET  /api/workspace-groups/state      → 全量快照
  └─ POST /api/workspace-groups/mutate     → 单条动作 {action, payload} → 新快照
Client 侧（client/client.js）
  ├─ 启动时拉全量快照 → 本地 store（乐观更新 + 防抖回写）
  ├─ 只读复用 DSH 既有数据：useWorkspaces / useSessions / useSessionStatus
  └─ 只写调用 DSH 既有动作：uiWorkspace.openSession / pickDirectory / archiveSession…
```

- Host 侧**不**接管工作区与会话的注册表，只存「分组视图元信息」（组、归组关系、排序、折叠、视图模式、归档）。
- 归组关系以 `workspaceId` 为键；工作区被删除后其记录成孤儿，前端渲染时忽略、Host 侧惰性清理。
- 存储写入使用「临时文件 + rename」原子替换，避免半写坏档；文件损坏时回退空状态并保留 `.bad` 备份。

### 2.3 状态模型（state.json）

```jsonc
{
  "version": 1,
  "groups": [
    {
      "id": "g_1a2b3c",
      "name": "游戏项目",
      "color": "teal",        // 预设色 key
      "icon": "code",         // 预设图标 key；"dot" 表示只显示小圆点
      "pinned": true,          // 置顶区
      "collapsed": false,      // 组折叠（默认展开）
      "order": 0,
      "createdAt": 1790000000000
    }
  ],
  "archivedGroups": [ /* 同结构 */ ],
  "assign": { "<workspaceId>": "g_1a2b3c" },          // 缺省 = 未分组
  "orders": {
    "g_1a2b3c": ["<wsId>", "<wsId>"],                 // 组内项目顺序
    "__ungrouped__": ["<wsId>"]                       // 未分组区顺序
  },
  "workspaceState": { "<wsId>": { "expanded": false, "showAll": false } },  // 项目折叠 / 查看全部
  "ui": { "view": "grouped", "collapsedAllAt": 0 }     // 视图模式
}
```

## 3. UI 设计

### 3.1 结构（分组树视图）

```
┌ 工作区 ─────────────────  ⇅视图 · ⊟全部折叠 · ＋分组 · ＋
│ [🔍 搜索：组 / 项目 / 对话...]
├ ── 置顶 ──────────────────────────────
│ ▍📁 游戏项目            ●3   [⋯]      ← 组头（细色条 + 着色图标 + 计数徽章）
│    ├ 📁 dungeons-…      (2 个对话)  [⋯]
│    │   ├ 对话标题 · 2h
│    │   └ 对话标题 · 昨天
│    │   └ 查看全部 7 个
│ ▍📁 前端重构            ⏱ 12m
├ ── 其他分组 ─────────────────────────
│ ▍⭐ 客户项目            ⏱ 3d
│    └（空组虚线框）拖项目到这里
├ ── 未分组 ───────────────────────────
│    📁 default-workspace (5 个对话)
│    （空态：把项目拖到这里移出分组）
└ 已归档 (2) ▸
```

- 组头：`chevron` + `2px 色条` + `着色图标/圆点` + `组名` + 右侧 `徽章/相对时间` + `⋯`。
- 项目行：缩进一级，`chevron` + 文件夹图标 + 名称 + `n 个对话`/最近时间 + `⋯`；折叠时下方只给最近 1–2 个对话 + 「查看全部 n 个」。
- 对话行：缩进两级，状态点（运行/待确认/未读完成）+ 标题 + 相对时间 + `…`。
- 拖拽反馈：目标行上方/下方 2px 强调色插入线；组头整体高亮 = 入组；「未分组」区高亮 = 移出。

### 3.2 色板（8–10 档，深浅双色）

`蓝 blue / 青 teal / 绿 green / 黄 amber / 橙 orange / 红 red / 粉 pink / 紫 violet / 靛 indigo / 石板 slate`

- 浅色主题：作为图标/圆点/细色条的中饱和色，落在浅底上对比 ≥ 3:1；
- 深色主题：同色相提亮一档（方案按主题属性/媒体查询切换，见 §6）；
- **只有** 图标、圆点、左侧细色条使用该色，正文/背景/行全部走 DSH 主题 token，避免大面积染色。

### 3.3 图标集（8 个通用）

`文件夹 folder`（默认）/ `星标 star` / `代码 code` / `文档 doc` / `方块 box` / `烧瓶 flask` / `火箭 rocket` / `Bug bug` / `圆点 dot`（仅色点，不画字形）

全部为 16×16 viewBox 的 stroke 图标（`currentColor`），由色板决定颜色。

## 4. 交互细则

### 4.1 拖拽（HTML5 DnD，本地实现）

| 起点 | 落点 | 结果 |
|---|---|---|
| 项目行 | 组头（含置顶组） | `assign[ws] = groupId`，并插入该组末尾 |
| 项目行 | 「未分组」区 / 未分组项目之间 | 删除 assign，插入未分组位置 |
| 项目行 | 同组内项目行缝隙 | 组内顺序调整（`orders[gid]`） |
| 组头 | 组头缝隙 / 置顶区 | 组排序（`groups[].order`），拖入置顶区自动 `pinned=true` |
| 任意 | 空组虚线区 | 入组（空组提示即落点） |

- `dataTransfer` 键：`application/x-dswg-workspace` / `x-dswg-group`（自识别，跨插件不抢事件）；
- 只接受本插件自己的拖拽类型，不干扰 DSH 其他拖拽（文件/标签）；
- 落点由「鼠标 Y 相对行中线」决定 before/after，组头整体高亮表示入组。

### 4.2 右键菜单

- **项目行**：`移动到组 →（列表：每个组 + 未分组 + 新建分组并移入）`、`重命名项目`、`删除项目`（复用 DSH 内置 workspace 菜单项）。
- **组头**：`重命名组`、`颜色`（10 色子菜单）、`图标`（8 图标 + 圆点子菜单）、`固定到顶部/取消固定`、`新建项目到本组`、`归档组`、`删除组…`。
- **对话行**：沿用 DSH 全局 `target: 'session'` 菜单（重命名/分支/复制 ID/置顶/归档）+ 本插件追加 `移动到组 →`（改的是所属工作区的归组）。

### 4.3 键盘

| 键 | 行为 |
|---|---|
| `↑` / `↓` | 在**可见**节点（组头、项目、对话行）之间移动焦点 |
| `→` | 展开当前节点（组 / 项目） |
| `←` | 折叠当前节点；已折叠则把焦点交给父节点 |
| `Enter` | 对话行 → 打开对话；组 → 切换折叠；项目 → 切换折叠 |
| `Ctrl/⌘ + Shift + F`（默认，可在 Saved Shortcuts 里改） | 全部折叠 |
| `Esc` | 清空搜索并回到树 |

- 树容器 `role="tree"`、行 `role="treeitem"` + `aria-expanded` + `aria-level`；行内 `tabIndex` 由 roving 焦点管理（同一时刻只有一个 `tabindex=0`）。
- 拖拽的**键盘替代**：右键菜单「移动到组 →」与组菜单即等价路径（无障碍要求）。

### 4.4 搜索

- 输入即筛（本地匹配，无需 Host 往返）：组名（含拼音无关的朴素子串）、项目名与路径 basename、对话标题；
- 结果分组显示，单条结果带路径前缀 `组名 › 项目名`；点击 → 展开所在组与项目 → 打开对话（组/项目命中则只展开并高亮定位）；
- `Enter` 打开首条命中；`Esc` 清空；
- 上限 80 条，超出提示「缩小范围」。

### 4.5 组头徽章与最近活跃

- 优先显示**计数徽章**：`待确认`（最高）→ `未读完成` → `运行中`，聚合到组内所有项目/对话，显示总数；
- 无上述状态时显示「最近活跃」相对时间（`just now / 8m / 3h / 昨天 / 3d`），复用 DSH 的 `relativeTime` 语义（本地实现，不引入 primitives 包）。

### 4.6 视图切换 / 归档 / 删除

- 视图：`分组树`（默认）/`最近使用`（全量对话按 `updatedAt` 倒序 + 路径标签），切换即持久化。
- 归档：组菜单「归档组」→ `archivedGroups`；底部「已归档 (n)」折叠区列出，可「恢复」。
- 删除组：模态框两按钮 —— `解散组（项目回到未分组）`（主按钮，默认焦点）/ `连同项目删除`（危险色，需二次勾选或二次确认文案）；`Esc`/`取消` 不产生任何写入；「连同项目删除」会调用 `workspaces.delete(wsId)`（仅注销登记，目录与对话日志保留）。

## 5. 持久化与一致性

1. Host 侧单一 `state.json`，写入串行化（内存队列 + Promise 链），每次动作：
   `apply(action) → 原子写盘 → 返回全量快照`。
2. Client 侧乐观更新：先改本地 store 再 `POST`；失败则回滚并提示（toast 走自绘，不依赖 primitives 包）。
3. 折叠状态**不需要**每次点击都等 Host 往返：本地立即生效 + 防抖 400ms 合并回写。
4. 首次启动：Host 返回 `version: 1` 空状态；若老版本状态文件字段缺失，按缺省补齐（向前兼容）。
5. 工作区被 DSH 删除后：`assign` 中的孤儿键在下次动作时惰性清理（渲染层同时忽略未知 wsId）。

## 6. 主题与无障碍

- 正文/边框/悬停一律用 `--dsw-alias-*` 主题 token（`label-primary/secondary/tertiary`、`bg-layer-*`、`border-l2`、`state-*`、`brand-primary`）；
- 自定义色板每档给出 `light` / `dark` 两个 hex；深色模式通过主题插件写入的根属性/媒体查询切换 `data-theme-dark` 分支（实现时以 `cordis_inspect_query Theme` + `ui-theme` 源码为准，绝不写死只对浅色生效的样式）；
- 焦点环：键盘焦点用 `outline: 2px solid var(--dsw-alias-brand-primary)` + `outline-offset: -2px`（不使用 `:focus-visible` 之外的颜色）；
- 折叠箭头 `aria-expanded`、组头 `aria-label="组 X，n 个项目"`、徽章 `aria-label="3 个待处理"`；
- 拖拽除了 DnD 还保留菜单路径；`prefers-reduced-motion` 下关闭展开动画。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 遮蔽 `sidebar.workspaces` 后原 Browser 的交互经验丢失（hover 按钮、目录流） | 用户感觉「少了东西」 | 右键菜单复用 DSH 内置 session/workspace 动作全量；目录选择走 `uiWorkspace.pickDirectory`；不声明子槽避免激活冲突 |
| 插件注册子槽与 `ui-workspace` 冲突导致激活失败 | 插件整体不生效 | 明确不声明任何子槽；只注册 `main`/`shell.overlay` 之外的既有 `list` 槽 |
| 折叠状态高频写盘 | IO 抖动 | 客户端防抖 400ms + Host 写队列串行 + 原子替换 |
| 色板在深色下刺眼 | 视觉噪音 | 每色双值 + 主题分支；只用于图标/圆点/细色条 |
| 工作区被外部删除产生孤儿 | 脏数据 | 渲染忽略 + 惰性清理 |
| 键盘焦点与 DSH 全局快捷键冲突 | 抢键 | 仅在树容器获得焦点时处理（`onKeyDown` 冒泡作用域内），不注册全局字母键；全部折叠用带修饰键的命令 |

## 9. 验证清单（交付时逐条核对）

1. `plugin_manager install_bundle` 后：`Config.listConfigs` 出现 `workspace-groups` 行、状态 `schema`；
2. `Slots.listSubTree(root: 'sidebar.workspaces')` 的 occupants 出现本插件 key，且原 `ui-workspace` 被遮蔽；
3. 页面左栏出现「组 → 项目 → 对话」三级树；新建组/改名/换色/换图标即时生效；
4. 拖拽入组 / 移出 / 组排序在刷新后仍保持（重启宿主后亦然）；
5. 删除组弹窗默认「解散组」，`Esc` 无副作用；
6. 搜索「组名/项目名/对话标题」三类命中，结果带组路径，点击可定位展开；
7. ↑↓←→/Enter 键盘导航与「全部折叠」快捷键生效；
8. 深色/浅色主题切换下色点与细色条均清晰、无大面积染色；
9. 刷新页面后折叠状态、视图模式、置顶与归档全部还原。

> 无浏览器自动化时：以 `cordis_inspect_query` 验证注册与占用，并对页面可见性做「安装即首个预览」的人工确认说明（不谎报视觉验证）。

### 9.1 第 2 条曾经骗过一次（已修正并加测）

`Slots.listSubTree` 里「本插件 key 出现在 occupants」这一条**本身不足以证明接管成功**。occupant 行还带 `priority` 和 `active`：

| 字段 | 在本槽的含义 |
| --- | --- |
| `priority: -1` / `0` | 两条 registration 的遮蔽排序（本插件 / 自带浏览器） |
| `active: true` | 该 entry 是当前单元格的赢家，真的在渲染 |
| `active: false` | 该 entry 已被退役（`abdicated`），渲染崩过，单元格回落给下一个幸存者 |

第一版交付时 inspect 报的是 `{ priority: -1, active: false }` + `{ priority: 0, active: true }` —— 注册成功，但渲染崩了，页面仍然是原生侧栏。原因是 `inject` 面写成了摊平形状（详见 DETAIL.md 第 1 节）。**所以核对第 2 条必须连 `active` 一起看**，看到 `active: false` 就等于「没接管」。这一条现在也出了自动化断言（`test/smoke.mjs` 的 inject 形状 + 接线错误面，`test/render.mjs` 的组合式渲染），不再只靠肉眼。

## 10. 明确的取舍

- **替换而非叠层**：这是唯一能真正改变左栏列表结构的位置；代价是必须自带「新增项目/搜索/创建组」等入口，已在计划中补齐。
- **单层分组**：不引入嵌套，换取拖拽与排序的确定性。
- **本地 JSON 存储**：不依赖 `storage-domain`（其 zod 依赖在插件安装路径上不一定可解析），用 node 内置 fs 原子写，行为可控、可备份。
- **不写 Session 事件**：分组元信息完全外置，绝不污染会话日志/格式迁移。
